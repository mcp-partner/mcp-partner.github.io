简介

MCP Partner 是一个用于调试和交互 Model Context Protocol (MCP) 的客户端工具。 你可以把它看作是 "MCP 界的 Postman"。它允许开发人员连接到 MCP 服务器，发现可用工具，并通过直观的 UI 执行这些工具。

新功能： 连接层已升级到官方 TypeScript SDK v2，可自动协商最新 2026-07-28 Streamable HTTP，并兼容 2025 legacy 与旧 HTTP+SSE 服务器。

⚡️ 无需安装。MCP Partner 作为渐进式 Web 应用 (PWA) 可以在浏览器中直接运行，并支持安装到本地桌面。

快速开始

1

连接服务器

在顶部地址栏输入您的 MCP 服务器地址。支持标准的 SSE 端点或 Streamable HTTP 端点。
示例：http://localhost:3000/sse (SSE) 或 http://localhost:3000/mcp (HTTP)

2

选择传输协议

优先选择 Streamable HTTP。只有使用 2024-11-05 独立 SSE + POST 端点的旧服务器才选择 SSE。

3

执行与调试

使用自动生成的表单填写参数，或切换到 JSON 视图进行原始编辑。点击 发送请求 即可运行工具并实时查看 JSON-RPC 响应。

核心功能

多协议支持

官方 SDK v2 自动兼容 2026 modern、2025 legacy Streamable HTTP，并保留 deprecated HTTP+SSE。

GitHub Pages 支持

纯静态架构，可完美部署于 GitHub Pages 等静态托管服务。

请求日志

底部控制台完整展示 JSON-RPC 流量，包含 Request ID、Method 以及详细的错误堆栈。

配置持久化

自动保存服务器列表、工具参数和执行结果。支持一键导出/导入 JSON 配置。

传输协议支持

SSE (Server-Sent Events)

旧协议兼容模式。客户端通过 GET 建立长连接，并从 endpoint 事件发现独立 POST 地址。该传输已被官方 deprecated。

Streamable HTTP

推荐模式。官方 SDK 会自动探测协议代际：2026-07-28 使用每请求 POST、metadata header 与请求级 SSE；2025 服务器自动回退到 initialize、可选 session/GET 流模式。

CORS 跨域与代理

浏览器强制执行严格的 CORS (跨域资源共享) 策略。如果您的本地 MCP 服务器没有发送正确的 Access-Control-Allow-Origin 头，浏览器将阻止连接。

典型症状：连接立即失败，并在日志中显示 "Network Error" 或 0 状态码。

解决方案

  1. 使用代理: 点击连接栏中的 🛡️ 图标。Vercel 部署可使用安全加固的内置 /cors?url=；GitHub Pages 不提供代理函数，请配置可信代理或服务器 CORS。
  2. 配置服务器: 允许 MCP Partner 的实际 origin，并允许协议所需 method/header。需要 credentials 时不得使用通配 origin。
  3. 使用 Pancors: 对于频繁的本地开发，推荐运行本地代理工具如 pancors。

服务器端 CORS 配置

如果您是 MCP 服务器的开发者，建议在服务器端正确配置 CORS 响应头：

// 使用实际前端 origin；如需 credentials，不能使用 "*"
w.Header().Set("Access-Control-Allow-Origin", "https://your-partner.example")
w.Header().Set("Access-Control-Allow-Methods", "GET, POST, DELETE, OPTIONS")
w.Header().Set("Access-Control-Allow-Headers", "Accept, Authorization, Content-Type, Last-Event-ID, MCP-Protocol-Version, Mcp-Session-Id, Mcp-Method, Mcp-Name")
w.Header().Set("Access-Control-Expose-Headers", "Content-Type, MCP-Protocol-Version, Mcp-Session-Id, Retry-After, WWW-Authenticate")
w.Header().Add("Vary", "Origin")

Header 作用说明：

Access-Control-Allow-Origin

允许实际 MCP Partner origin；认证场景应使用精确 origin

Access-Control-Allow-Methods

2026 使用 POST；旧 Streamable/SSE 还可能使用 GET 与 DELETE

Access-Control-Allow-Headers

还需允许 2026 的 MCP-Protocol-Version、Mcp-Method、Mcp-Name 与动态 Mcp-Param-* header

Access-Control-Expose-Headers

让 SDK 读取 Content-Type、旧 session header 与 WWW-Authenticate

Vary: Origin

按请求 origin 动态返回 CORS 时避免缓存混淆

连接失败排查步骤：

  1. 检查浏览器控制台错误 - 打开开发者工具查看 Console 和 Network 标签页
  2. 验证预检请求 - 检查 OPTIONS 请求的响应头是否包含 CORS headers
  3. 测试最小配置 - 先用最基本的三个 header 测试连接
  4. 检查协商版本 - Connected 日志会显示 modern/legacy 与实际 protocol version

安装为桌面浏览器壳

推荐：如果服务器 CORS 或代理已经可用，请直接点击 Chrome / Edge 地址栏中的安装图标来安装标准 PWA。图标由浏览器自动取得，所有安全机制保持开启。

GitHub Pages 不能运行服务端代理。对于你明确可信的开发服务，可以用下面的安装器创建一个独立 Chromium --app 窗口。它不是 Electron，不打包浏览器，不需要管理员权限，并会自动处理图标。

高风险模式：专用 profile 会关闭同源/CORS 保护。这个窗口只能打开 MCP Partner；不要登录账号、安装扩展或浏览其他网站。点击“不再显示”后，提示会永久关闭并保存在此专用 profile 中。

下载安装器

创建桌面和开始菜单快捷方式，自动下载 ICO；仅本次 PowerShell 子进程使用 Bypass，不修改系统策略。

$Installer = Join-Path $env:TEMP 'install-mcp-partner-windows.ps1'

Get-Content $Installer
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $Installer

与原 Linux 启动项相比

  • --app 后使用普通 URL，不使用 Markdown 链接格式。
  • 专用 profile 放在用户数据目录；Chromium 要求 --disable-web-security 与 --user-data-dir 同时使用。
  • 移除不必要的 --test-type 和过时的 SecFetchMetadata feature 名，也绝不忽略 TLS 证书错误。
  • Chrome 142+ 可能显示 Local Network Access 提示；只允许你信任的本地 MCP 服务。

使用 --uninstall（Windows 为 -Uninstall）删除快捷方式并保留 profile；使用 --purge / -Purge 同时删除专用 profile。此模式不能绕过服务器认证、服务端 Origin 拒绝、TLS 证书错误或网络故障。

Introduction

MCP Partner is a client-side debugging and interaction tool for the Model Context Protocol (MCP). Think of it as "Postman for MCP". It allows developers to connect to MCP servers, discover available tools, and execute them with an intuitive UI.

New: The connection layer now uses the official TypeScript SDK v2 to negotiate 2026-07-28 Streamable HTTP and remain compatible with 2025 legacy and HTTP+SSE servers.

⚡️ No installation required. MCP Partner runs entirely in your browser as a Progressive Web App (PWA).

Quick Start

1

Connect to a Server

Enter the URL of your MCP server in the top bar. The application supports standard SSE (Server-Sent Events) and Streamable HTTP endpoints.
Example: http://localhost:3000/sse

2

Select Transport

Prefer Streamable HTTP. Select SSE only for a legacy 2024-11-05 server with separate SSE and POST endpoints.

3

Execute & Debug

Fill in the parameters using the auto-generated Form view or switch to JSON view for raw editing. Click Send to execute the tool and view the JSON-RPC response in real-time.

Key Features

Multi-Protocol

Official SDK v2 support for modern 2026 and legacy 2025 Streamable HTTP, plus deprecated HTTP+SSE compatibility.

GitHub Pages Ready

Pure static architecture, ready to deploy on GitHub Pages or any static host.

Request History & Logs

View full JSON-RPC traffic in the bottom console, including request IDs, methods, and full error stacks.

State Persistence

Your server list, tool parameters, and execution results are saved locally, so you can pick up where you left off.

Supported Transports

SSE (Server-Sent Events)

Legacy compatibility mode. A GET stream advertises a separate POST endpoint. The transport is officially deprecated.

Streamable HTTP

Recommended. The SDK negotiates 2026 per-request POST/metadata/SSE behavior and automatically falls back to the 2025 initialize/session era.

CORS & Proxying

Browsers enforce strict CORS (Cross-Origin Resource Sharing) policies. If your local MCP server does not send the correct Access-Control-Allow-Origin headers, the browser will block the connection.

Symptoms of CORS issues: Connection failing immediately with "Network Error" or 0 status code logs.

Solutions

  1. Use Proxy: Click the 🛡️ icon. Vercel deployments can use the hardened built-in /cors?url= Function. GitHub Pages has no proxy Function; configure server CORS or a trusted proxy.
  2. Configure your Server: Allow the actual MCP Partner origin and all protocol methods/headers. Never use a wildcard origin together with credentials.
  3. Use Pancors: For heavy local development, run a local proxy like pancors.

Server-Side CORS Configuration

If you're developing an MCP server, it's recommended to properly configure CORS response headers:

// Use the actual app origin; credentials cannot be combined with "*"
w.Header().Set("Access-Control-Allow-Origin", "https://your-partner.example")
w.Header().Set("Access-Control-Allow-Methods", "GET, POST, DELETE, OPTIONS")
w.Header().Set("Access-Control-Allow-Headers", "Accept, Authorization, Content-Type, Last-Event-ID, MCP-Protocol-Version, Mcp-Session-Id, Mcp-Method, Mcp-Name")
w.Header().Set("Access-Control-Expose-Headers", "Content-Type, MCP-Protocol-Version, Mcp-Session-Id, Retry-After, WWW-Authenticate")
w.Header().Add("Vary", "Origin")

Header Explanations:

Access-Control-Allow-Origin

Allow the actual MCP Partner origin; use an exact origin for authenticated access

Access-Control-Allow-Methods

2026 uses POST; legacy Streamable HTTP/SSE can also use GET and DELETE

Access-Control-Allow-Headers

Include MCP-Protocol-Version, Mcp-Method, Mcp-Name, and dynamic Mcp-Param-* headers

Access-Control-Expose-Headers

Let the SDK read Content-Type, legacy session headers, and WWW-Authenticate

Vary: Origin

Prevents cache confusion when CORS is generated for each request origin

Troubleshooting Connection Issues:

  1. Check Browser Console - Open DevTools to view Console and Network tabs
  2. Verify Preflight Requests - Check if OPTIONS responses include CORS headers
  3. Test Minimal Configuration - Start with just the three essential headers
  4. Check Negotiation - The Connected log shows the modern/legacy era and negotiated protocol version

Install a desktop browser shell

Recommended: if server CORS or a trusted proxy already works, use the install icon in the Chrome or Edge address bar. The standard PWA obtains its icon automatically and keeps browser security enabled.

GitHub Pages cannot run a server-side proxy. For an explicitly trusted development service, the installers below can create an isolated Chromium --app window. This is not Electron, does not bundle a browser, requires no administrator access, and installs its icon automatically.

High-risk mode: same-origin and CORS protections are disabled in the dedicated profile. Use this window only for MCP Partner; never sign in, install extensions, or browse other sites. Select “Don't show again” to dismiss the notice permanently in this profile.

Improvements over the original Linux entry

  • The --app value is a plain URL, not Markdown link syntax.
  • The dedicated profile lives in user data; Chromium requires --user-data-dir for --disable-web-security.
  • Unnecessary --test-type and the obsolete SecFetchMetadata feature name are omitted; TLS errors are never ignored.
  • Chrome 142+ can prompt for Local Network Access. Allow only a local MCP service you trust.

Use --uninstall (-Uninstall on Windows) to remove shortcuts but keep the profile; use --purge / -Purge to delete the dedicated profile too. This mode cannot bypass server authentication, a server-side Origin rejection, TLS certificate errors, or network failures.
